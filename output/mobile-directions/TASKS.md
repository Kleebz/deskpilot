# Eight workflow scripts

For the current `/spaces` trial, start in its recent terminal. Open Spaces, find a native task and switch between its terminal panes. Create a local space and task, move an ordinary terminal and a Codex conversation into that task, then switch and reload with separate drafts. Use the tab-bar + to create an empty task and exercise Start terminal and Add existing work. Open the same preview in another browser: organization should match while drafts remain separate. Edit in both browsers and resolve the stale save through explicit refresh. Use Needs you across computers; check the computer name when opening a result. In Test states, remove Herdr and verify the local space still works. Remove the local organization and confirm work returns to Unassigned with its draft. Computer retains the shared desktop, preview, pairing, recovery and settings tasks below.


The selected combined direction is `/combined`. Review Sessions/search/recent work, the dedicated Attention inbox and explicit cross-computer review, and Computer tools in this route. The scripts below also preserve the original A/B/C comparison protocol; C is retained as history and is not the selected direction.

Use the same phone, viewport, and fixtures for A (`/focus`), B (`/inbox`), and C (`/explorer`). Reset each direction with **Test states → Reset this direction’s fixtures** before a fresh run. Counterbalance the direction order across people. Record completion, time, mistaken destinations, backtracking, and comments; do not treat automated checks as user-study results.

| Task | Participant instruction | Expected outcome and observations |
| --- | --- | --- |
| 1. Find work among twenty items | Find “Fix the reconnect race…” on Studio, connect to it, then find both terminals named “shell.” | Search is visible; the exact Codex conversation is explicit before Connect. Two ordinary shells remain distinct by folder and ID. In C, root search can include all computers; Herdr has its own branch. Record time and search discovery. |
| 2. Read and respond | Open Studio’s `deskpilot` terminal. Read its request, open the phone keyboard, and reply “Continue.” Use Input tools to type a path without Enter, select output, change text size, and inspect input history. | Terminal remains readable; composer is generous; prompt and paste actions have different semantics. Simulated input identifies its recipient. Measure terminal space and targets at 320/360/390/430px and landscape. On Android, record actual keyboard visibility and retention. |
| 3. Switch without losing a draft | Draft a reply in `deskpilot`, visit two neighboring terminals using swipes and previous/next, write a different draft, and return. Open the title picker and search for another item. Reload. | The composer remains mounted across neighbors; each identity retains its own draft and separate paste draft; reload restores the selected view. Nothing submits automatically. Record whether title switching, swiping, and accessible arrows are found unaided. |
| 4. Review and return to the correct place | In B, start Review across computers and continue to Build server. In A/C, open a terminal from a filtered search, then from Desktop screen 2. Switch several times and use Back. | B visibly identifies every computer and returns to Attention; A/C session swipes stay on one computer. Search query, filter, scroll, selected screen, and native tab restore. Swipes replace the terminal history entry. Android Back dismisses the physical keyboard first; next Back leaves the view. |
| 5. Use native organization and management | Find Product → Mobile → Frontend in Herdr. Visit its sibling pane. Create a space, tab, and split with a directory/command. Rename and reorder; review closing a tab, simulate a changed subtree, and attempt closure. Re-review and close. | Native space/tab/pane scope stays visible in the terminal. Swipes stay in one native tab. Stale closure is rejected; a current review lists all affected IDs/generations. Disconnect mobile view preserves original work; Stop Herdr terminal stops the exact source. Cross-space transfer is explicitly unavailable. |
| 6. Use desktop controls | Find Desktop without instructions. Select/swipe workspaces, open an associated terminal and return, move its window, tile windows, capture and enlarge a screen/window. Lock, attempt capture, then unlock. Switch to Build server. | Captures are explicit; locked capture is refused. Placement reflects the chosen desktop; a newly created terminal defaults to that workspace. Headless Desktop explains unsupported capability while Sessions and Previews remain accessible. No real desktop operations occur. |
| 7. Inspect and publish a preview | Find Previews; select Fixture assembly, enlarge it, use actual-size and fit, refresh, publish an example image, and remove it. | History, caption, timestamp, dimensions, and image controls are accessible. Publication works independently of terminal connection. No matching task name establishes ownership. Record navigation cost from an active terminal. |
| 8. Pair, administer, and recover | From Computer settings → Machines & pairing, begin pairing and cancel. Try QR, expired code, and example success. Rename a device and revoke access. Exercise notifications, usage, diagnostics, and browser preferences. Draft a reply, then simulate offline, reconnecting, unauthorized, and unknown status. Recover without sending. | Pairing cancellation returns to the same subsection and control. Credential failure preserves drafts; retry/re-pair never replays them. Computer and browser scope are explicit. Coverage gaps never imply all-clear. Test state controls affect only fixtures. Record whether computer tools and recovery are discoverable. |

For task 5, additional native actions live in **Manage this space & tab**. Stop a single program from **terminal → Session actions → Stop Herdr terminal**. To test unavailable management, select Build server or toggle Herdr management in Test states; attachment and ordinary terminals remain available.

Use **Escape** to exercise the prototype’s keyboard-first Back logic on a desktop keyboard. Test Android’s real Back separately. Repeat tasks 2–4 on a physical Android Chrome/PWA shortcut before choosing a production direction; check Safari/iOS compatibility afterward.

The task scripts cover the eight workflow groups implied by the design plan. The plan did not provide an older, separately numbered set of eight scripts.
